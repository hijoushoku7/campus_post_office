# 要件定義書：セキュアファイル共有アプリ（自宅サーバー / Docker）

> ステータス: ドラフト v0.1
> 最終更新: 2026-06-07

## 1. 背景・目的

GIGAファイル便のような「大容量ファイルを手軽に受け渡せる」体験をベースにしつつ、
**身内のプロジェクトメンバーがログインして安全に使う**ことを前提とした、
自宅サーバーで運用する Web アプリを構築する。

- 公開サービスではなく、限定メンバー向けの **クローズドな共有基盤**。
- 大容量ファイルの **一時的な受け渡し** が主用途（長期保管庫ではない）。
- デプロイ・運用は **Docker（docker compose）** で完結させ、保守性を重視する。

## 2. 前提・決定事項（ヒアリング結果）

| 項目 | 決定 |
|------|------|
| 認証方式 | **アカウント制（ログイン必須）**。全操作にログインを要求 |
| ファイル上限 / 保存期間 | **〜10GB / 7日**（短期・自動削除） |
| 共有方式 | **ログイン必須の共有リンク**（リンクを開くにはログインが必要） |
| 技術スタック | おまかせ（本書の推奨構成を採用） |
| セキュリティ重視点 | **通信暗号化（HTTPS必須）／ ウイルススキャン ／ 操作ログ・監査** |
| 公開方法 | **Cloudflare Tunnel**（cloudflared）で自宅サーバーを公開。ポート開放不要 |
| ストレージ | **ローカルファイルシステム**（MinIO等のオブジェクトストレージは使わない） |
| 運用環境 | 自宅サーバー、Docker |

> 保存時暗号化（at-rest）は今回の必須要件には含めない。ただし将来の拡張余地として §9 に記載。

### ⚠️ 重大な制約：Cloudflare のアップロードサイズ上限
Cloudflare（Tunnel 含む）は **1 リクエストのボディサイズに上限**がある。

| プラン | 1リクエスト上限 |
|--------|-----------------|
| Free / Pro | 100MB |
| Business | 200MB |
| Enterprise | 既定500MB（引上げ申請可） |

- **10GB ファイルを一括 POST するとブロックされる**ため、
  **チャンク分割した再開可能アップロード（各チャンク < 100MB、安全側で 50MB 程度）が必須**。
- ダウンロード（レスポンス）側にはこの上限は適用されないため、10GB DL は可能。
  ただし全トラフィックが Cloudflare を経由する点は許容する（帯域・遅延）。
- 将来 Business 以上にすればチャンクを大きくできるが、設計はチャンク前提で固定する。

## 3. スコープ

### 3.1 対象（MVP）
- ユーザーのログイン / ログアウト
- ファイルのアップロード（最大10GB、再開可能）
- ファイル一覧・詳細表示
- ファイルのダウンロード
- 有効期限（7日）による自動削除
- アップロード時のウイルススキャン
- 操作ログ（監査ログ）の記録・閲覧（管理者）
- 管理者によるユーザー管理（招待・無効化）

### 3.2 対象外（今回やらない）
- 一般公開・匿名ダウンロード
- ファイルのプレビュー / 編集機能
- フォルダ階層・同期クライアント
- 課金・容量プラン管理
- 外部 SSO（OIDC/SAML）連携 ※将来拡張

## 4. 想定ユーザー / ロール

| ロール | 権限 |
|--------|------|
| 管理者 (admin) | 全機能 + ユーザー管理 + 全ファイル管理 + 監査ログ閲覧 |
| 一般ユーザー (member) | 自分のアップロード / ダウンロード / 自分のファイル削除 |

- **要確認**: 想定同時利用人数・総ユーザー数（数人〜十数人を仮定）。
- ユーザー登録は **管理者による招待制**（自由登録は不可）。
- メール送信は使わない（**手動運用**）ため、招待は **招待リンクを管理者が発行 → 口頭/チャットで手渡し** する方式。

## 5. 機能要件

### 5.1 認証・アカウント
- メールアドレス + パスワードによるログイン。
- パスワードはハッシュ化保存（Argon2id 推奨）。
- セッションは HttpOnly / Secure Cookie。
- **招待制**: 管理者が招待リンク（トークン付き・有効期限あり）を生成し、手動で対象者へ渡す。
  招待された人はリンクからメール＋パスワードを設定してアカウント作成。
  （メール自動送信は行わない。代替として管理者が直接アカウントを作成する手段も用意してよい）
- ログイン失敗のレート制限・アカウントロック。
- **2要素認証(TOTP)は MVP では見送り**（将来拡張）。

### 5.2 アップロード
- 最大 **10GB / ファイル**。
- **再開可能（resumable）アップロード**：ネットワーク断でも続きから。
- 複数ファイル同時アップロード対応。
- アップロード進捗表示。
- アップロード完了後、非同期でウイルススキャン → `scanning` → `ready` / `infected` に状態遷移。
- スキャン中はダウンロード不可。
- **感染検出時は対象ファイルを自動削除**し、監査ログに記録のうえ **管理者へ通知**。
  メールは使わないため通知は **アプリ内（管理者ダッシュボードのアラート）** で行う。
  アップロード者にもアプリ内で「感染のため削除」を表示する。

### 5.3 ファイル管理
- 自分がアップロードしたファイルの一覧（ファイル名・サイズ・状態・残り期限）。
- ファイルごとの **有効期限（デフォルト7日、上限内で短縮可）**。
- 期限切れファイルは自動削除（ストレージ + メタデータ）。
- 手動削除も可能。
- ダウンロード回数の上限設定（任意機能、将来）。

### 5.4 ダウンロード / 共有（ログイン必須の共有リンク方式）
- アップロード後、ファイルごとに **共有リンク**（推測困難なトークン付きURL）を発行。
- 共有リンクを開くには **ログイン必須**。未ログインならログイン画面へ誘導し、認証後に対象ファイルへ戻す。
- ログイン済みであれば、リンクを知っている人はダウンロード可能。
- リンクには **有効期限**（ファイルの期限と連動、最大7日）を設定。期限切れリンクは無効。
- ダウンロードは大容量に対応するため **ストリーミング / Range リクエスト（再開DL）対応**。
- ダウンロード時に監査ログ記録。
- 任意機能（将来）: リンクの手動失効、ダウンロード回数上限、リンク個別パスワード。

> 補足: 「アカウント制ログイン」＋「ログイン必須リンク」の二段構えにより、
> 部外者はリンクを入手してもログインできず DL 不可。身内限定の安全性を確保する。

### 5.5 監査ログ
- 記録対象: ログイン/失敗、アップロード、ダウンロード、削除、ユーザー管理操作。
- 記録項目: 日時、ユーザー、操作、対象ファイル、IPアドレス、結果。
- 管理者が閲覧・検索可能。
- 保存期間の方針を決める（例: 90日）。

## 6. 非機能要件

| 区分 | 要件 |
|------|------|
| 性能 | 10GBアップロード/ダウンロードが安定動作（チャンク/ストリーミング） |
| 可用性 | 自宅サーバー前提。再起動後に自動復帰（restart policy） |
| セキュリティ | 全通信 HTTPS（TLS）。ウイルススキャン。監査ログ。CSRF/XSS対策 |
| バックアップ | DB の定期バックアップ。ファイル本体は短期のため任意 |
| 保守性 | docker compose 一式で起動。設定は環境変数で集約 |
| ストレージ | アップロード容量に応じたディスク監視・上限管理 |

## 7. 推奨技術構成

```
[ブラウザ]
   │  HTTPS（TLSはCloudflareエッジが終端）
   ▼
[Cloudflare エッジ]  ← DNS / TLS / WAF。アップロードは1リクエスト100MB上限
   │  Tunnel（cloudflared がアウトバウンド接続。ポート開放不要）
   ▼
[cloudflared]（自宅サーバー内コンテナ）
   │  内部HTTP
   ▼
[リバースプロキシ: Caddy/Nginx（任意・内部ルーティング用）]
   │
   ├──► [Web/App: Next.js (App Router, TypeScript)]
   │        - 認証(Auth.js/Lucia), UI, API(Route Handlers)
   │
   ├──► [tus サーバ]   再開可能チャンクアップロード（各チャンク<100MB）→ ローカルFSへ
   ├──► [PostgreSQL]   メタデータ・ユーザー・共有リンク・監査ログ
   ├──► [Redis]        ジョブキュー（スキャン・期限削除）
   ├──► [ClamAV]       ウイルススキャン
   └──► [Worker]       非同期処理（スキャン / 期限切れ削除 / 通知）

[ローカルFSボリューム]  ファイル本体（Dockerボリューム / ホストのディスク）
```

### 採用理由（要点）
- **Cloudflare Tunnel**: 自宅サーバーをポート開放・固定IPなしで安全に公開。TLSはCloudflareが終端するため Let's Encrypt 不要。
- **Next.js + TypeScript**: フロント/バック一体でモダン、保守しやすい。
- **再開可能アップロード（tus プロトコル）**: チャンクを 50MB 程度に分割し、
  Cloudflare の 100MB 上限を回避しつつ 10GB を安定送信。ネットワーク断でも再開可。
  ローカルFS保存と相性が良い（tus-node-server のファイルストア）。
- **ローカルFS**: MinIO 不要で軽量。短期受け渡し用途に十分。ホストのディスク容量監視は必須。
- **ストリーミング DL + Range 対応**: 10GB を低メモリで配信、再開DLも可能。
- **ClamAV + Worker(Redis/BullMQ)**: 大容量スキャンを非同期化し UX を確保。
- すべて Docker イメージあり → `docker compose up` で一括起動。

> セキュリティ強化オプション（将来）: Cloudflare Access を前段に置けば、
> アプリ到達前にメール認証（Zero Trust）でブロックでき多層防御になる。今回は任意。

## 8. データモデル（ドラフト）

- **users**: id, email, password_hash, role, is_active, created_at
- **files**: id, owner_id, original_name, size, storage_path, status(uploading/scanning/ready/infected/expired), expires_at, created_at
- **share_links**: id, file_id, token(推測困難), expires_at, revoked_at, download_count, max_downloads(任意), created_at
- **upload_sessions**: id, user_id, tus_id, bytes_uploaded, total_size, completed_at（再開アップロードの進捗管理）
- **audit_logs**: id, user_id, action, target_file_id, ip, result, created_at
- **invitations**: id, email, token, expires_at, accepted_at

## 9. 将来拡張（任意）

- 保存時暗号化（at-rest encryption）
- ダウンロード回数制限・ワンタイムリンク
- 外部SSO（OIDC）連携
- 通知（メール/チャット）連携
